1. 專案背景與目標 (Background & Objectives)

傳統早餐店與麵點專賣店具備「品項流轉快、早晚班交接頻繁、對帳計算複雜」之營運特性。本系統旨在提供一套**離線優先 (Offline-First)、雙向即時同步、全自動算帳與資安防護無縫接軌**之管理工具。

💡 系統核心發展目標
  • 精準分區盤點：自動承接昨留結存，提供「架位 1~5 + 桌面」實地盤點，自動演算銷量包數與顆數。
  • 早晚班無縫對帳：早班結業現金自動滾動為晚班開市底層金，搭配硬幣紙鈔面額拆解。
  • 離線優先 0 延遲：網路斷線時系統依然 100% 可用，恢復連線後 0.4 秒極速自動同步。
  • 無露天資安防護：透過 Firebase REST API 與 Database Secret 密鑰認證，阻擋非法讀寫並消除系統警報信。

3. 資訊安全與存取控制 (Security Architecture)

系統拋棄傳統易洩漏帳密方式，採用 **Firebase Database Secret (系統特許密鑰)** 進行伺服器級對接。

3.1 驗證金鑰與通訊端點

const FIREBASE_DB_URL = 'https://jean-breakfast-default-rtdb.firebaseio.com';
const FIREBASE_PATH   = '/baozi-data';
const FIREBASE_SECRET = 'W0IDCTDBafaAIhvQEyUyH5qIZLD06tFqfShPXCbi';

function getDbEndpoint() {
    return `${FIREBASE_DB_URL}${FIREBASE_PATH}.json?auth=${FIREBASE_SECRET}`;
}

3.2 Firebase 資安規則設定

Firebase 控制台 Rules 設定為完全關閉公開權限：

{
  "rules": {
    ".read": false,
    ".write": false
  }
}

完全安全 外部未帶密鑰之連線一律拒絕 (HTTP 401)，持密鑰之合法系統可 100% 讀寫通暢。

4. 核心功能性需求 (Functional Requirements)

4.1 存貨盤點與庫存管理模組 (FR-1)

  • 15 大常態商品主檔： 鮮肉包, 蔥花捲, 豆漿饅頭, 起司捲, 五穀雜糧饅頭, 黑糖包, 黑糖饅頭, 芋泥包, 芋頭饅頭, 芋頭地瓜捲, 南瓜饅頭, 南瓜起司包, 芝麻紅豆捲, 芝麻饅頭, 巧克力起司捲。
  • 昨留結存繼承：自動搜尋最近實際營業日，繼承當日之「結業剩餘」為今日「昨留結存」。
  • 分區盤點公式：
    結業剩餘 (包) = 架1 + 架2 + 架3 + 架4 + 架5 + 桌面
    當日銷售 (包) = (昨留結存 + 當日入庫) - 結業剩餘
    銷售顆數 = 當日銷售包數 × 3
  • 低庫存警示：結業剩餘包數低於預設警示值 (< 8 包) 時，自動觸發補貨警示卡片。

4.2 早晚班對帳與收銀管理模組 (FR-2)

  • 早上對帳公式：早上營業額 = (早上結業現金 + 早上貨款支出) - 早上開市底層金
  • 晚班自動滾動接續：下午班開市底層金自動帶入「早上結業現金」。
  • 面額拆解計算：支援紙鈔 (1000/100)、50元、10元、5元、1元硬幣個數自動加總。

4.3 成本會計與損益攤提模組 (FR-3)

  • 變動成本管理：內建常用支出範本（麵粉進貨、豬肉食材、瓦斯更換、包裝耗材、水電雜支、白米糯米、地瓜粉、雞蛋等）。
  • 固定成本攤提公式：單日攤提固定成本 = (每月固定成本 + 每月員工薪資) ÷ 30
  • 每日淨利算式：每日純利 = 今日總營業額 - (當日變動成本 + 單日攤提固定成本)

4.4 雙向即時雲端同步模組 (FR-5)

  • 極速上傳防抖 (400ms)：欄位輸入完畢後 0.4 秒自動完成 REST API 推送。
  • 自動背景對接 (10s)：頁面保持開啟時，每 10 秒自動檢查一次雲端資料庫。
  • 分頁喚醒對齊：解鎖手機或切換瀏覽器分頁 (visibilitychange / focus) 時自動下拉最新數據。
  • 智慧動態對齊 (Smart Diffing)：僅更新非焦點輸入框 (el !== document.activeElement)，打字完全不卡頓。
  • JSON 備份還原：支援一鍵匯出全庫 JSON 檔案，或選擇歷史 JSON 備份檔 1 秒覆寫還原。
